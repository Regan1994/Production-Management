# 生管系統需求與流程基準

更新日期：2026-11-19（Asia/Taipei）  
狀態：第一階段需求基準，尚未進行功能改造

## 1. 系統目的

本系統以既有的組裝報工功能為基礎，建立供業助使用的生產管理系統。

系統要管理的是每一台已組裝完成機台的製號，以及該製號後續的訂單安排、半成品庫存與機型統計。所有日常資料在系統內操作；只有現場需要紙本或管理需要外部資料時，才依選擇的條件列印或下載。

本系統不以複製既有 Excel 的分頁結構為目標。Excel 總表中的有效規則將轉為系統資料與自動統計，避免由業助在多份檔案之間重複核對或加減數量。

## 2. 範圍與系統邊界

### 生管系統負責

- 組裝報工建立製號、START 與 FINISH。
- 已完成製號進入生管資料。
- 依製號管理機型、零件註記、配單與噴漆完成日。
- 依機型管理半成品庫存、訂單需求、排產與統計。
- 依條件產生現場文件、清單、Excel 或 PDF。

### 目前不納入

- 校機資料庫的功能或資料整合。
- 噴漆完成後的校機、檢驗、包裝與出貨操作。
- 尚未確認的五軸「組」手動報工方式。
- 舊 Excel 資料的正式匯入與切換。

校機系統仍是業務確認機台是否進入檢驗環節的獨立系統。生管系統的交接終點是噴漆完成，不應讓校機資料反向成為生管的核心資料來源。

## 3. 核心名詞與資料原則

| 名詞 | 定義 |
| --- | --- |
| 製號 | 一台實體機台的唯一標準識別，也是整個生管流程的主鍵。 |
| 機型 | 該實體機台本身的型號。 |
| 單號 | 業務訂單。排單時將特定製號安排給特定單號。 |
| 半成品 | 已完成組裝、有製號與機型，但尚未配單、未噴漆、未轉校機的機台。 |
| 可用庫存 | 所有符合半成品定義的製號集合；庫存數量是該集合的筆數。 |
| 成品 | 已填寫噴漆完成日、已轉交校機的機台。 |

### 不可違反的資料原則

1. 一台實體機台只有一個製號。
2. 製號與機型是機台固有資料；單號是後續安排結果。
3. 庫存不可只保存數量，必須保留每一台可用機台的製號。
4. 所有統計數量須能追溯至實際製號清單。
5. 同一製號在同一時間只能有一個有效配單。
6. 系統資料是唯一真相；列印品與匯出檔是當下資料的輸出，不可成為另一個手動維護來源。

## 4. 組裝報工到生管的交接

組裝報工是生管的資料出發點。現有系統已在 `job_run` 中保存製號、機型快照、組裝階段、狀態與 FINISH 時間。

### 一般機型

```text
建立製號與報工批次
→ START
→ FINISH
→ 建立一筆可由生管管理的機台資料
→ 未配單時列入可用半成品庫存
```

尚未 FINISH 的製號只屬於組裝中的機台，不能列入庫存或供業助配單。

### 五軸機型

同一五軸製號的組裝工時分為四段：

1. 旋
2. 傾
3. 尾
4. 組

旋、傾、尾分別組裝，各自保留一筆工時。最後的「組」是將三者組成完整機台，也必須保留一筆工時。

五軸製號必須滿足旋、傾、尾、組都已完成，才算一台完整機台，才可進入生管、半成品庫存與配單清單。四筆工時在員工報表中仍各自計算；庫存與機型產量只能算一台。

現場的「組」沒有料單，無法使用現有貼於料單上的掃碼流程。最終操作方式待確認，在此之前不可將「組」FINISH 的掃碼列為必要條件。

## 5. 訂單與配單

單號不是製號的永久屬性。急單與訂單修改常會造成已配機台被挪用，因此系統必須支援在噴漆前解除配單與改配。

```text
半成品製號
→ 配給訂單 A
→ 解除或改配
→ 配給訂單 B
```

改配時系統必須自動做到：

- 製號目前只顯示有效的新單號。
- 原訂單立即回到待安排機台的狀態。
- 新訂單取得該製號。
- 半成品庫存、待配訂單與機型統計立即重算。
- 自動保存改配歷程，避免要求業助額外填寫重複紀錄。

## 6. 庫存、統計與排產

所有統計需依機型分開計算，供業助判斷歷史製造量、目前可用庫存，以及下次是否需要補做。

每個機型至少應提供：

- 已組裝完成總數。
- 可用半成品製號清單與數量。
- 已配單、尚未噴漆的製號清單與數量。
- 已噴漆、已轉交校機的數量。
- 訂單需求與尚未配到機台的數量。
- 排產總數與預計補庫存量。

「安排組裝 10 台、已有訂單 5 台」要區分兩個概念：

- 預計補庫存為 5 台。
- 實際庫存必須等每台 FINISH、取得製號且尚未配單後才成立。

例如已組裝製號 1–10，已配單製號為 2、5、7、9、10，則可用庫存必須顯示製號 1、3、4、6、8，並自動顯示數量 5。

## 7. 文件、列印與匯出

文件一律由系統資料產生，不建立需額外手動維護的 Word 或 Excel 總表。

### 現場作業文件

- 一般機型的組裝料單與 START／FINISH 條碼。
- 五軸旋、傾、尾的料單與條碼。
- 五軸「組」的現場操作方式待決，不預設使用料單或條碼。

### 管理與業助輸出

- 依機型的可用半成品製號清單。
- 待配訂單清單。
- 已配單、尚未噴漆清單。
- 指定期間的組裝完成清單。
- 依機型的庫存、需求、排產與待補統計。

文件中心的共通流程應為：

```text
選擇文件類型
→ 篩選機型、日期、狀態或製號
→ 預覽
→ 下載 Excel、PDF 或列印
```

## 8. 已確認的實作順序

1. 需求與流程基準（本文件）。
2. 生管資料模型與資料庫 migration。
3. 一般機型與五軸完成機台的生管交接判定。
4. 半成品庫存與機型統計。
5. 訂單、配單與改配。
6. 排產與預計補庫存。
7. 文件中心、匯出與列印。
8. 從 2026 訂單總表及既有庫存表進行資料對帳與匯入規劃。
9. 使用真實資料平行驗收後再切換現場流程。

## 9. 尚待確認的決策

1. 同一張單號是否可以包含多個機型，以及同一機型是否可要求多台。
2. 五軸「組」的開始與完成由誰、以什麼畫面或設備操作；是否需同時保留開始與完成時間。
3. 排產功能是否需正式建立排產安排，並記錄組裝人員與預計完成日，或只需保存各機型的計畫數量。
4. 零件註記是否只做追溯，或會限制哪些機台可配給哪些訂單。
5. 哪些現場紙本、Excel 與管理文件必須保留，哪些可由畫面取代。
6. 舊資料匯入的範圍：僅匯入仍有效訂單與現存半成品，或連同歷史資料一併匯入。

## 10. 目前不應做的事

- 不直接把四份 Excel 的分頁與固定儲存格公式搬入系統。
- 不把尚未 FINISH 的組裝中製號算入可用庫存。
- 不把五軸旋、傾、尾任一單段 FINISH 當作完整機台。
- 不讓使用者手動加減庫存數量。
- 不要求業助在生管系統和組裝報工系統重複建立同一製號。
- 不在本階段整合校機資料庫。
